## 首次 Agent 初始化修复与验收边界

SubLang v1.0.0 未实现“首次采用宿主 Agent/模型，取不到则使用约定默认值，随后固定、只由用户修改”的新规则；旧版本失败记录保留。
v1.0.1 增加了运行入口初始化，但真实调用在先检查 settings 时误把记录缺失当成配置冲突而停止。v1.0.2 增加 preflight，明确先准备再检查；未初始化时的 settings 不启动 Core、不生成凭据优先的默认配置。宿主显式传递、一次初始化、后续保持、新 Player 继承及用户主动重新配置继续保留。默认模型分别为 Codex gpt-6.1-sol / Claude claude-opus-5-5。
v1.0.3 只将 npm 运行时 @sublang/playbook 升级为 18.1.4，复用旧 Core，导致内置 SPEX 内容包仍由 18.1.3 生成。两者是不同格式的包，但内置内容来自 npm Playbook，应在同次构建中生成；不能以“包不同”解释并忽略混合构建。
v1.0.4 将 SPEX 上游 420aba7b 的存储实现重新构建进 CLI 制品，保留现有 Core 并通过其导入的 SPEX 文件/环境库生效；两份制品的来源分别记录在 release.json.artifactSources。新增原生 Windows 只读授权存在于 Core 启动前/启动后的 package-add 回归，检查安装字节、版本、锁文件、入口和已有目录 ACL 不变；不执行被测四工作流。
初始化配置和真实 Core 的确定性回归不调用模型，不等于四工作流手动验收通过。旧会话保留原 Agent 快照；新版配置需通过新会话验证。
初次使用必须如实核对默认行为，不预先配置正确答案。
错误默认值或需要人工预配记 FAIL；认证/模型不可用记 BLOCKED，停止主路线；用户主动重新配置单独记录，不覆盖首次结果。
普通继续使用可检查配置是否稳定；未安全实测凭据变化的子场景写 NOT_RUN，不能声称已全覆盖。

## 证据边界

- 安装、宿主发现、运行时准备、市场搜索、安装包、入口可运行、真实模型执行分别判断。
- readiness 是静态检查，不是目标模型实际调用成功。
- CI 冒烟只证明其实际范围；四个业务工作流不进入 CI。
- 退出 0、ok:true、一轮结束不代替原工作流终态、人工 Gate、独立审查和产物证据。
- 人工 Gate 等待写 WAITING；无法证明终态写 BLOCKED/未证明，不用另开流程冒充原完成。
- 相同模型、不同 Player ID 可进行独立角色审查；不合并 coder/reviewer。
- 关闭代码覆盖率不免除选定场景的用例评估；结构错误不可忽略。
- 测试只覆盖 Hello 的一个最小正常变化，不代表全量产品或未实测的其他 OS/宿主组合。
- 不修改认证、不擅自开启全权、不上传凭据或个人 SPEX 数据；Codex 使用运行时正常的 .git 沙箱写入配置，不推送测试分支。

v1.0.5 将 CLI、Core、内置内容从同一上游 420aba7b 加随发布公开的源码补丁重新构建，使用上游锁文件安装依赖；两份制品携带同一构建记录，源码树、补丁和锁文件哈希可核验。npm Playbook 和生成的内置 sublang/playbooks 均为 18.1.4，Core 协议为 36。runtime-check 由实际 Core 返回其来源及各工作流静态引擎导入的实际解析路径；新运行在来源或选定工作流引擎无法对齐时拒绝提交。

Playbook/SLC 内部 npm @sublang/spex@3.0.0 属于它们声明的 ^3.0.0 API 依赖，不强制覆盖成 Core 使用的 5.0.0。外部工作流内容包的声明版本不等于它实际导入的执行引擎版本，必须分别取证。已有用户内容锁定版本不自动改写；本轮全新环境期望内置内容为 18.1.4。

自动回归覆盖独立运行时来源、内置内容、合成 Playbook 安装、旧缓存引擎链接修复和真实依赖目录保留/运行前拒绝，不执行四个手动验收工作流，也不替代明镜机器上的复测。


v1.0.6 来自实际 Codex workspace-write 验收发现的缺陷：preflight 启动 Core 时 fs.watch 异步 EMFILE 导致未处理异常。修复为原生监听同步/异步失败时自动目录轮询，保留配置/会话变更观察，不改权限、不提高 ulimit。macOS 18 项回归及原 Codex 沙箱定点回归通过；Windows 同组测试加入 CI，结果单独取证。本修复不等于 12 步或四工作流全部通过。
